## Bugs and changes

1. **Refresh lost the library and selected Workspace:** metadata lived only in React memory. The frontend now stores document references and selected page/tab in sessionStorage, refetches actual metadata on restoration, removes 404 references, rejects mismatched identities and offers retry on connection failures. It does not cache readiness or summaries. Separate tabs/accounts/devices are not synchronized. A rapid tab-click/refresh edge remains open.
2. **Publication metadata was absent despite successful extraction:** LlamaParse native footer/header elements were excluded from Markdown chunks. `markdown-pages-v2` adds only existing native margin text with original page attribution, skips bare page numbers/duplicate text and preserves saved extraction. Existing v1 records require explicit reprocessing; user papers were not reprocessed. Default 1,200-character chunks and target 150-character overlap remain unchanged.
3. **A paper question containing “generally” skipped retrieval:** general-intent detection matched that word anywhere. Bare “Generally, …” is now restricted to the start; explicit general-background phrases remain supported. Regression tests pass; its live post-fix answer is **BLOCKED**.
4. **READY could display endless summary waiting after a model-profile change:** summary reads correctly reject a saved result for a different profile, but UI treated every 409 as active work. READY+409 now shows an unavailable-summary message instead of claiming ongoing analysis. Automatic regeneration for changed profiles was not added.
5. **Summary repair lacked the draft and complete correction locations:** strict validation rejected inaccurate quote references. Feedback now includes all invalid source paths and a bounded previous draft for targeted repair, without relaxing quote/page checks or changing the workflow profile version. Deterministic tests pass; a successful full-paper live repair after this final change is **BLOCKED**. This is not a measured accuracy improvement.

**Open failure:** the last cached browser run recorded 7 PASS / 1 FAIL. Its failed summary/refresh assertion showed the prior Chat tab after an immediate click/reload ([screenshot](qa/2026-11-14-live/cached-failure-3.png), [raw checks](qa/2026-11-14-live/cached-final-browser.json)). Earlier stable Summary refresh passed. The rapid timing edge was not fixed or independently reproduced before disposable records were deleted; it remains an explicit follow-up, not a claimed pass.

Earlier harness failures are also retained privately: `innerText` was compared to a different text-normalization assertion, one initializer reset navigation on every reload, and an aborted chat route was left installed after a preceding assertion failed. The final cached checks corrected those harness issues. They made zero chat POST requests. The final rapid-refresh failure above is separately retained.
